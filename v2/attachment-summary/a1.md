# A1: Read-only inventory and usage scan

Parent plan: `v2/attachment-summary.md` (read its section 2 "nothing may break" first).
Page: **Custom Thumbnail Generator > Attachment Summary** (`admin.php?page=ctgen-attachment-summary`).

## Goal

A Media Library-style table of every image attachment on the current site that shows
where each image is uploaded to and where it is actually used, with a batched,
resumable usage scan. Nothing about images, files, posts or options is changed.

## Decisions taken for A1 (from the plan's open decisions)

- **D1 - usage sources.**
  - By file path (every size, `-scaled`, edited `-e123...` versions and WebP copies;
    plain and JSON-escaped `\/` paths): content of every post type except revisions,
    attachments, auto-drafts and changesets; every custom field (labels for Elementor,
    Beaver Builder, Divi/others shown as "custom field"); every option except transients.
  - By attachment ID: featured image (`_thumbnail_id`), `wp-image-ID` class, block
    attribute `"id":ID`, gallery shortcode `ids`, gallery block `"ids":[...]`, WooCommerce
    product gallery (`_product_image_gallery`), site icon, active theme's custom logo and
    header image, image and gallery widgets.
  - Not scanned: term meta, user meta, files on disk (theme templates, CSS), external sites.
    The UI says "No usage found", never "Unused".
- **D2 - cache.** Per attachment post meta `_ctgen_usage` (references, scan time, scanner
  version) and `_ctgen_usage_count` (number, for filtering and sorting). These are the only
  writes A1 makes. `uninstall.php` removes both keys.
- **D9 - scope.** Current site only (multisite: per site). Media offloaded to S3/CDN shows
  "not stored locally" for sizes; the scan still works (it searches the database).

## Page

- Scan bar: "Scan all images", "Scan images not scanned yet", progress bar, live status
  (throttled), one run at a time, 2-minute request timeout, stop after 3 consecutive errors.
- List table (`WP_List_Table`): Image (preview, title, file name, edit/view links),
  Type (format, dimensions), Uploaded to, Used in (count, expandable list with links and
  source labels, scan time, Rescan), Current size (total of all local files, per-file list),
  Status (WebP copies present for N of M files / not convertible).
- Filters: type, attached/unattached, usage (found / none found / not scanned); search by
  title and file name; sort by title, date, type, uploaded to, usage count; pagination with a
  per-page screen option.
- Batches of 10 images per request; per-row Rescan updates only that row.

## Gate (all re-run with evidence, like M1-M4)

1. Scanner finds a fixture image referenced in each supported way (content `<img>`, srcset
   only, block attribute only, `wp-image-ID` only, gallery shortcode, gallery block, featured
   image, JSON-escaped builder data, custom-field URL, WooCommerce gallery, widget option,
   site icon, theme logo) with the right source label.
2. No false positives: same file name in another month folder, `photo2.jpg` vs `photo.jpg`,
   revisions and auto-drafts are not reported.
3. Attached-but-unused and used-but-unattached images are shown correctly.
4. Database writes are limited to the two cache keys: `wp_posts` and `wp_options` checksums
   unchanged, postmeta changes only in those keys; uploads unchanged.
5. AJAX: nonce + `manage_options`, IDs only, no paths in responses, bad input rejected.
6. Browser: table renders all columns; scan all / scan unscanned / per-row rescan work and
   the UI matches the stored results; filters, search, sorting and pagination work;
   keyboard access and live region; no console errors.
7. Performance measured on a large fixture set (hundreds of images and posts).
8. `php -l`, JS checks, PHPCS 0, Plugin Check on the release build clean; existing M1-M4
   suites still pass.
