2. WHAT WAS BUILT
-----------------
Page: Custom Thumbnail Generator > Attachment Summary.
- includes/class-ctgen-usage-scanner.php: read-only scanner. Finds an image
  by file path (all sizes, -scaled, edited -e123 versions, WebP copies; plain
  and JSON-escaped slashes) in post content, custom fields and options, and by
  ID in wp-image-ID classes, block attributes, gallery shortcodes/blocks,
  featured images, WooCommerce galleries, site icon, theme logo and header,
  image/gallery/block widgets. Exact regex check after a LIKE prefilter.
  Skips revisions, attachments, auto-drafts, changesets, transients.
- includes/class-ctgen-attachment-summary.php: page, scan bar, AJAX
  ctgen_usage_get_ids / ctgen_usage_scan (nonce + manage_options, IDs only,
  1-25 per request), screen option, shared "Used in" cell.
- includes/class-ctgen-attachment-summary-table.php: WP_List_Table with Image,
  Type, Uploaded to, Used in, Current size, WebP status, Date; filters (type,
  attached, usage), file-name search, sorting (title, type, parent, usage,
  date), pagination with an "Images per page" screen option.
- assets/js/ctgen-attachment-summary.js (+ .min.js built by v2/tools),
  assets/css/ctgen-attachment-summary.css.
- uninstall.php: removes _ctgen_usage, _ctgen_usage_count and the per-page
  user setting; keeps custom sizes, images and WebP copies.
- Wiring: includes/init.php, includes/settings-page.php. readme.txt and .pot
  updated.
Data written by A1: only the two post meta keys on scanned images.

4. ISSUES FOUND AND FIXED DURING A1
-----------------------------------
- Table showed no rows: column headers were not set in prepare_items(). Fixed.
- TEST LEFTOVERS (mine): every browser-test login since M3 landed on the
  Dashboard, whose Quick Draft box created an auto-draft owned by the
  temporary user; deleting the user moved it to the trash. 32 trashed
  "Auto Draft" posts + 32 revisions had accumulated. Removed (DB backed up
  first); the admin user's own auto-draft (ID 447) and 7 older theme-style
  revisions were left untouched. All browser tests now log in straight to the
  plugin page and permanently delete anything the test user owns.
- The runner now fingerprints options, posts and postmeta from outside the
  test processes at start and end. Over two complete runs plus a final A1 run
  the database was identical (WPForms caches, Action Scheduler locks, cron and
  transients excluded: other code rewrites them on every admin page load).

5. LIMITATIONS
--------------
- Detection cannot cover theme files, CSS, term/user meta or other websites;
  the UI says "No usage found", never "unused".
- Scan time grows with database size (one database search per image). Large
  sites can scan in several sessions with "Scan images not scanned yet".
- Results are a snapshot ("Scanned 5 mins ago"); they are not updated
  automatically when content changes. Use Rescan.
- Not tested: multisite, media offloaded to S3/CDN, page builders other than
  the Elementor-style JSON fixture, browsers other than Chromium.
