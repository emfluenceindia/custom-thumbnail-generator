2. WHAT CHANGED
---------------
Settings page (user-visible):
- New "Convert All Thumbnails to WebP" button (#ctgen-webp-convert-all) in a
  new section below the regenerate controls, with its own progress bar
  (#ctgen-webp-progressbar), current-image line, counts line, live status
  (#ctgen-webp-status, role=status, aria-live=polite) and failure list.
- The GIF notice moved into this new section.
- Default sizes table: new "Action" column with a "WebP" button per row.
- Custom sizes table: a "WebP" button after the regenerate/remove buttons.
- Row buttons: class .ctgen-webp-convert-size, data-slug, accessible name
  "Convert <size> thumbnails to WebP".

Files:
- includes/init.php: ctgen_enqueue_webp_scripts() - settings page only;
  wp_localize_script('CTGENWebpConvert') with nonce + 18 translatable strings.
- includes/class-ctgen-functions.php: Action column +
  ctgen_render_webp_convert_button() (shared by both tables).
- templates/ctgen-form-html.php: WebP section markup.
- templates/ctgen-custom-thumb-list-html.php: WebP button per row.
- NEW assets/js/ctgen-webp-convert.js (readable source)
- NEW assets/js/ctgen-webp-convert.min.js (built from the source)
- NEW assets/css/ctgen-webp-convert.css
- The existing assets/js/ctgen-media-actions.min.js and
  assets/css/ctgen-admin.min.css are untouched (byte-identical).

Client behaviour:
- Discovery request, then one request per image, sequential (100 ms gap).
- Each response is validated (success flag, numeric counts that add up to
  the number of sizes) before any counter moves.
- Per-image server error (e.g. image deleted mid-run): counted, listed, run
  continues. Malformed/network error: counted, listed, run continues;
  3 in a row stop the run. 403 / "-1": stops at once (session expired).
  Unknown/missing size: stops at once (would repeat for every image).
- One run at a time: all WebP buttons disabled during a run, plus a run lock
  that also stops programmatic clicks.
- Live region updated only at start, 25/50/75 % and at the end.

Dev tooling (v2/, not shipped):
- v2/tools/package.json (pinned terser 5.49.0, playwright-core 1.48.2),
  installed offline from the local npm cache.
- v2/tools/build-js.js: builds the .min.js; --check fails on drift.
- v2/tests/m3-browser.js, m3-legacy-ui.js, m3-fixtures.php.
- .gitignore: added /v2/tools/node_modules/ (see 5).

4. CAVEATS
----------
4.1  Item 5: the per-row regenerate button is not pixel-identical. Its CSS
     and box size are identical, but the custom-table cell now centres three
     buttons instead of two, so the button starts at a different sub-pixel
     position and the recycle icon's anti-aliased edge differs (52 edge
     pixels). The remove button is pixel-identical after a 1 px shift.
     Side-by-side: v2/tests/results/m3-legacy/row-regen-side-by-side.png
4.2  Item 5: per-row regenerate and remove used stubbed server responses
     (the real ones rewrite all real media / the real option); their real
     backend behaviour is covered by the M2 harness (item 22).
4.3  Item 10 failures are simulated with Playwright request interception.
4.4  Console errors in the run come only from the deliberately injected
     failures (3 aborted requests, 2 x 403).


4.5  Layout change after this report: the Default Thumbnails table now sits
     under the Custom Thumbnails table in the right-hand column
     (templates/ctgen-form-html.php wraps both in #ctgen-tables-column;
     includes/settings-page.php no longer renders it separately; one CSS
     rule aligns the right edges). Re-run afterwards: browser suite 17/17,
     legacy UI capture identical to the previous M3 capture except the
     script ?ver (1.0.2 -> 1.1, same sha256) and 7 anti-aliasing pixels
     (max 3/255) on the Regenerate button border after a run; PHPCS 0;
     Plugin Check on the release build: no errors.
